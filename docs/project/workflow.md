# 仓库维护工作流程

本文件承接 `AGENTS.md` 的检查点与验证细则，只用于仓库维护；安装后的数学 Skill 不读取项目进度或执行发布流程。

## 执行与检查点

1. 按 `AGENTS.md` 完成开工检查，定位适用规范及完成条件。复杂任务给出简短计划；已有授权的维护直接执行，不重复申请实施许可。
2. 实质修改前刷新 `progress.md` 的 `[Checkpoint]`。一个逻辑相关文件组、一次完整审计或一类验证为一个步骤；同一步骤内的查询不单独记账。
3. 完成一个步骤后，先核验结果，再更新检查点及受影响的 `[Done]`、`[Doing]`、`[Next]`、`[Bugs]`，复读确认后进入下一步骤。长测试在启动前和获得结果后分别记录。
4. 同步受影响的事实来源：产品要求变更更新 SPEC、对应分层规范和追踪矩阵；纠错更新 lessons；持久阶段或恢复背景变化更新胶囊。未受影响的文件无需制造修改。
5. 交付前检查 diff 和工作区，说明改了什么、实际验证、剩余问题及安装/提交/推送/发布状态。

检查点保留以下字段，可用简短条目，不复制整份计划或历史报告：

- 任务与目标；
- 授权范围与禁止动作；
- 最近完成步骤与证据路径；
- 当前步骤；
- 本任务修改文件与未提交状态（不混入用户原有改动）；
- 下一项精确动作；
- 阻断项、待决定事项及外部动作；
- 恢复指令。

## 压缩与恢复

- 可控或可预见的上下文压缩前暂停新工作，刷新检查点，记录中断位置、产物、测试结果和下一动作；核对 Git 状态，检查胶囊是否仍准确，必要时更新。两份文件均须复读确认。
- 瞬时 Git 状态和当前步骤只存检查点；胶囊只保留持久事实及恢复入口，避免两份状态互相覆盖。
- 无预警压缩后按 `AGENTS.md` 恢复，核对检查点、Git diff 和实际产物，补齐缺失事实后继续；不重复已完成工作。
- 写入失败先处理失败；不得声称检查点已保存。平台压缩不可控制时，恢复后补审计，不声称能阻止平台行为。

## 按影响范围验证

验收数量、阻断项及顺序以 [测试规范](../spec/07-testing-acceptance.md) 为准。

| 修改类型 | 应执行的验证 |
|---|---|
| 仓库治理、链接、进度或拼写 | diff、引用、规范一致性；不重跑数学题 |
| 纯输出排版 | 结构检查及输出类合成用例 |
| Skill 指令删重、路由或流程重构 | 结构、规范映射及全部 24 个公开合成用例；保留实际输出与观察证据 |
| 数学方法、范围、条件或阻断缺陷修复 | 失败用例 → 同类用例 → 全部固定回归（最低 36 道）；必要时新的未见题 |
| 首次交付或变更后需要完整重新验收 | 至少 24 个合成、36 道固定、12 道未见题，依测试规范执行 |

结构检查覆盖 frontmatter、目录名、相对链接、一层引用、可移植性、YAML 解析、资源边界及 `git diff --check`。使用 `skill-creator` 快速校验器；缺依赖时不安装，记录实际失败并使用已有工具做等价检查。`skills-ref` 可用时运行。

行为验证必须执行请求并观察输出；静态关键词命中、阅读旧报告或预测模型会如何回答不算运行通过。前向验证可使用当前环境允许的独立子 Agent：只给请求、Skill 和必要上下文，不给答案或修复结论；输出放隔离临时目录。子 Agent 回传可公开的短结果与验证摘要，不只回传临时路径；维护者审查后立即归档。公开原创用例可保存完整输出，真题只保存定位、短结果和核验摘要，原文留在临时目录。

全部必要检查通过后结束验证；只有新改动、失败或未解决风险才扩大范围。历史报告保留日期和执行者，不能改写成当前版本的测试结论。已解封题不再称为新的盲测，不用其答案调优。

## 纠错

明确指出错误事实，搜索受影响表述，修正直接错误与派生引用；在 `lessons.md` 记录“现象 → 原因 → 防止规则”，再验证。长期规则只维护一个执行落点，其他文档引用该落点，避免每次事故都扩大全部任务的固定流程。
